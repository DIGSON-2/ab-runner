# AB Runner

AB Runner - desktop-приложение на Electron для ручной и массовой отправки HTTP-запросов. По смыслу это легкий Postman + Runner: можно хранить коллекции запросов, использовать окружения, подставлять данные из JSON-файла, запускать сценарии, писать pre-request/post-response scripts и смотреть подробную историю.

## Возможности

- Коллекции, папки и запросы.
- Вкладки открытых запросов сверху с настраиваемым лимитом.
- Методы `GET`, `POST`, `PUT`, `PATCH`, `DELETE`.
- Headers, Authorization, Body и Scripts для каждого запроса.
- Body типов `None`, `Form-data`, `URL Encoded`, `Raw`, `Binary`, `GraphQL`.
- Raw JSON с форматированием, комментариями и простой автопочинкой незакрытых скобок.
- Окружения с переменными вида `{{baseUrl}}`, `{{token}}`.
- Платформы с быстрой подстановкой `{{platform}}` для переключения хоста.
- Подстановка данных Runner вида `{id}`, `{user.email}`.
- Одиночная отправка запроса через `Send`.
- Массовый запуск коллекции через Runner по JSON-файлу.
- История запросов с URL, headers, body, статусом и ответом, включая ошибочные запросы.
- Импорт из Postman, Postman environment и cURL.
- Backup/export и restore/import всех данных приложения.
- JSON Generator для подготовки файлов данных.
- Темы интерфейса.

## Основные понятия

`Коллекция` - группа запросов для одного API, сервиса или рабочего сценария.

`Папка` - способ сгруппировать запросы в левой панели.

`Запрос` или `Шаг` - один HTTP-запрос: название, метод, URL, headers, authorization, body и scripts.

`Окружение` - набор переменных, например `baseUrl`, `token`, `username`, `password`.

`Runner` - массовый запуск запросов по массиву объектов из JSON-файла.

`Открытые запросы` - верхняя панель вкладок с запросами, которые сейчас открыты в редакторе.

## Интерфейс

Слева находится основная панель:

- выбор окружения;
- управление окружениями;
- поиск по коллекциям и запросам;
- дерево папок и запросов;
- кнопка `{} JSON` для JSON Generator;
- кнопка `Postman` для импорта Postman-файлов;
- кнопка `Папка` для создания папки;
- кнопка `Запрос` для создания нового запроса;
- меню `Данные` для backup/export и restore/import;
- переключатель темы;
- кнопка скрытия панели.

Сверху находится область `Открытые запросы`.

- Счётчик показывает, сколько запросов открыто, например `Открытые запросы 3/10`.
- Поле `Лимит` задаёт максимум открытых вкладок сверху.
- Значение лимита сохраняется локально.
- Если открыть больше запросов, чем разрешено лимитом, самая старая неактивная вкладка сверху закроется.
- Запрос из коллекции при этом не удаляется.
- Вкладку можно закрыть крестиком или средним щелчком мыши.

В центре находится редактор выбранного запроса:

- название запроса;
- HTTP-метод;
- URL;
- кнопки `Send`, `cURL`, `Удалить`;
- вкладки `Headers`, `Authorization`, `Body`, `Scripts`.

Внизу редактора находится Runner:

- выбор JSON-файла с данными;
- задержка между запросами;
- запуск коллекции;
- таблица результатов;
- вкладка истории.

## Быстрый старт

1. Нажмите `Запрос` в левой панели.
2. Введите название запроса.
3. Выберите HTTP-метод.
4. Укажите URL.
5. При необходимости заполните `Headers`, `Authorization`, `Body`, `Scripts`.
6. Нажмите `Send`, чтобы отправить запрос один раз.
7. Для массового запуска выберите JSON-файл в Runner и нажмите `Запустить`.

Пример URL:

```text
{{baseUrl}}/users/{id}
```

Если в окружении есть `baseUrl`, а в файле Runner есть поле `id`, приложение подставит оба значения.

## Переменные и подстановки

AB Runner поддерживает два вида подстановок.

Переменные окружения:

```text
{{baseUrl}}
{{token}}
{{username}}
{{password}}
```

Данные текущего объекта Runner:

```text
{id}
{email}
{user.email}
{delivery.address.city}
```

Пример файла для Runner:

```json
[
  {
    "id": 1,
    "user": {
      "email": "first@example.com"
    }
  },
  {
    "id": 2,
    "user": {
      "email": "second@example.com"
    }
  }
]
```

Если URL выглядит так:

```text
{{baseUrl}}/users/{id}?email={user.email}
```

то для первого объекта он превратится в:

```text
https://example.com/users/1?email=first@example.com
```

## Окружения

Окружение удобно использовать для значений, которые меняются между стендами:

- `baseUrl`;
- `token`;
- `username`;
- `password`;
- `warehouseId`;
- любые другие переменные.

Как пользоваться:

1. В верхней части левой панели выберите окружение.
2. Нажмите кнопку управления окружениями.
3. Создайте новое окружение.
4. Добавьте переменные.
5. Используйте их в URL, headers, body или scripts через `{{name}}`.

Пример:

```text
Authorization: Bearer {{token}}
```

## Платформы

Платформа нужна, когда у разных стендов меняется только первый сегмент хоста.

Например вместо отдельных окружений для `goa-rostov`, `ekb`, `msk` можно хранить общий URL так:

```text
http://{{platform}}.wmsx.fmlogistic.ru/wh/v1/supplies/{id}
```

В левой панели выберите окружение, затем выберите или добавьте платформу для этого окружения. У каждого окружения свой список платформ, поэтому `wmsx.fmlogistic.ru` и `paradigma.fmlogistic.ru` можно держать раздельно. Активная платформа автоматически доступна как переменная:

```text
{{platform}}
```

Так окружение может хранить общие `username`, `password`, `token` и свой домен, а переключение между платформами выполняется отдельным селектором внутри выбранного окружения.

## Headers

Во вкладке `Headers` добавляются пары ключ/значение.

Пример:

```text
Content-Type: application/json
Accept: application/json
Authorization: Bearer {{token}}
```

Каждый header можно включать и выключать чекбоксом.

## Authorization

Во вкладке `Authorization` выбирается тип авторизации.

Если запрос не требует авторизации, оставьте `No Auth`.

Если токен уже есть в окружении, чаще всего достаточно добавить header:

```text
Authorization: Bearer {{token}}
```

Если токен нужно получать автоматически, используйте вкладку `Scripts` и pre-request script. Старый подход `auto token` больше не нужен.

## Body

Во вкладке `Body` выберите тип тела запроса.

`None` - тело не отправляется.

`Form-data` - multipart form-data, подходит для полей и файлов.

`URL Encoded` - `application/x-www-form-urlencoded`.

`Raw` - сырой текст: JSON, JavaScript, XML, HTML или plain text.

`Binary` - отправка файла как бинарных данных.

`GraphQL` - GraphQL query и variables.

### Raw JSON

Для JSON обычно выбирайте `Raw` и формат `JSON`.

Пример:

```json
{
  "id": "{id}",
  "email": "{user.email}",
  "status": "active"
}
```

Перед отправкой `{id}` и `{user.email}` будут заменены значениями из текущего объекта Runner.

Raw JSON поддерживает комментарии:

```json
{
  "id": "{id}",
  // обычный комментарий
  "type": "support",
  /* block comment */
  "active": true
}
```

Также поддерживаются строки-комментарии вида:

```text
/type: support
```

Такие комментарии игнорируются при отправке JSON.

Кнопка форматирования:

- красиво форматирует JSON;
- понимает комментарии;
- может автоматически закрыть недостающие `}` и `]`;
- если ошибку нельзя исправить, показывает место проблемы.

Если JSON body сломан, приложение остановит отправку и покажет ошибку до запроса к серверу.

### Binary

Для отправки файла:

1. Выберите тип `Binary`.
2. Нажмите `Выбрать файл`.
3. Убедитесь, что имя файла появилось в поле.
4. Нажмите `Send` или запускайте Runner.

## Scripts

Во вкладке `Scripts` можно писать JavaScript-код для запроса.

Есть два режима:

- `Pre-request` - выполняется перед основным запросом.
- `Post-response` - выполняется после получения ответа.

Pre-request удобно использовать для:

- получения токена;
- обновления headers;
- изменения body;
- пропуска запроса;
- остановки Runner;
- подготовки данных.

Post-response удобно использовать для:

- проверки ответа;
- сохранения значений из ответа в окружение;
- логирования;
- остановки Runner при ошибке.

### Доступный API `pm`

Окружение:

```js
pm.env.get('token');
pm.env.set('token', 'value');
pm.env.unset('token');
pm.env.all();
```

Запрос:

```js
pm.request.url;
pm.request.method;
pm.request.headers.get('Authorization');
pm.request.headers.set('Authorization', 'Bearer token');
pm.request.headers.remove('Authorization');
pm.request.headers.has('Content-Type');
pm.request.headers.all();
pm.request.body.get();
pm.request.body.set({ name: 'Alex' });
```

Данные текущего объекта Runner:

```js
pm.request.data;
```

Ответ:

```js
pm.response.status;
pm.response.statusText;
pm.response.headers;
pm.response.body;
pm.response.data;
pm.response.time;
```

Дополнительные команды:

```js
await pm.sendRequest({ method, url, headers, body });
await pm.runStep('Название шага');
pm.log('message');
pm.skip('reason');
pm.abort('reason');
pm.expect(value).toBe(expected);
```

### Пример: получить токен перед запросом

```js
let token = pm.env.get('token');

if (!token) {
  const login = await pm.sendRequest({
    method: 'POST',
    url: '{{baseUrl}}/auth/token',
    headers: {
      'Content-Type': 'application/json'
    },
    body: {
      username: pm.env.get('username'),
      password: pm.env.get('password')
    }
  });

  token = login.data.token;
  pm.env.set('token', token);
}

pm.request.headers.set('Authorization', `Bearer ${token}`);
```

### Пример: изменить body перед отправкой

```js
const body = pm.request.body.get();

body.requestId = pm.request.data.id;
body.sentAt = new Date().toISOString();

pm.request.body.set(body);
```

### Пример: проверить ответ

```js
pm.expect(pm.response.status).toBe(200);

if (!pm.response.data.success) {
  pm.abort('API вернул success=false');
}
```

### Пример: сохранить значение из ответа

```js
if (pm.response.data.token) {
  pm.env.set('token', pm.response.data.token);
}
```

## Одиночная отправка через Send

Кнопка `Send` отправляет выбранный запрос один раз.

Если запрос использует плейсхолдеры `{id}` или `{user.email}`, приложение откроет окно тестовых данных. Заполните значения и отправьте запрос.

Горячая клавиша:

```text
Ctrl+Enter
```

На macOS:

```text
Cmd+Enter
```

## Runner

Runner нужен для массового запуска запросов по JSON-файлу.

Как использовать:

1. Подготовьте JSON-файл с массивом объектов.
2. Откройте нужный запрос или коллекцию.
3. В нижней панели нажмите `Выберите файл`.
4. Выберите JSON-файл.
5. При необходимости задайте задержку между запросами в миллисекундах.
6. Нажмите `Запустить`.
7. Следите за прогрессом и таблицей результатов.

Пример файла:

```json
[
  {
    "id": "A-100",
    "amount": 1200,
    "client": {
      "phone": "+10000000000"
    }
  },
  {
    "id": "A-101",
    "amount": 900,
    "client": {
      "phone": "+20000000000"
    }
  }
]
```

В запросе можно использовать:

```text
{id}
{amount}
{client.phone}
```

Если pre-request script вызывает:

```js
pm.skip('reason');
```

текущий запрос будет пропущен.

Если script вызывает:

```js
pm.abort('reason');
```

Runner остановится.

## История

История хранит выполненные запросы и ответы.

В истории можно посмотреть:

- фактический URL;
- метод;
- статус;
- request headers;
- request body;
- response headers;
- response body;
- ошибку, если запрос не прошёл.

Важно: request body показывается и для успешных, и для неуспешных запросов. Это помогает анализировать ошибки API.

Как открыть детали:

1. Откройте вкладку `История`.
2. Найдите нужную запись.
3. Дважды щёлкните по строке.
4. В модальном окне посмотрите URL, headers, body и ответ.

Также есть глобальная кнопка `История`, которая показывает общую историю приложения.

Старые записи, которые были сохранены до появления request body в ошибках, могут не содержать body. Новые записи сохраняют body.

## Импорт

AB Runner поддерживает импорт:

- cURL-команд;
- Postman collection;
- Postman environment.

Postman:

1. Нажмите `Postman` в левой панели.
2. Выберите `Выбрать файлы` или `Выбрать папку`.
3. Выберите JSON-файлы Postman.
4. Дождитесь импорта.

cURL:

1. Откройте запрос.
2. Нажмите `cURL`.
3. Вставьте cURL-команду.
4. Импортируйте её в текущий запрос или как новый шаг.

## Backup и восстановление данных

Меню `Данные` в левой панели содержит:

- `Экспорт backup`;
- `Восстановить backup`.

Backup содержит:

- коллекции;
- папки;
- окружения;
- историю;
- recent/open-related данные приложения.

Как сделать backup:

1. Откройте меню `Данные`.
2. Нажмите `Экспорт backup`.
3. Выберите место сохранения JSON-файла.

Как восстановить backup:

1. Откройте меню `Данные`.
2. Нажмите `Восстановить backup`.
3. Подтвердите действие.
4. Выберите backup-файл.

Восстановление заменяет текущие коллекции, окружения и историю данными из backup-файла.

## JSON Generator

JSON Generator помогает быстро создать JSON-файл для Runner.

Используйте его, когда нужно подготовить массив объектов без ручного написания большого JSON.

Общий порядок:

1. Нажмите `{} JSON`.
2. Добавьте поля.
3. Укажите значения.
4. Сгенерируйте JSON.
5. Сохраните файл.
6. Используйте файл в Runner.

## Где хранятся данные

Данные приложения сохраняются локально в папке пользовательских данных Electron.

Обычно там есть:

- `ab-runner-data.json` - коллекции, папки, окружения и настройки приложения;
- `ab-runner-history.json` - история запросов.

Для обычного пользователя удобнее использовать меню `Данные` и backup-файл, а не редактировать эти файлы вручную.

## Частые проблемы

### Не подставляется `{{baseUrl}}`

Проверьте, что выбрано правильное окружение и в нём есть переменная `baseUrl`.

### Не подставляется `{id}`

Проверьте, что Runner запускается с JSON-файлом, где у каждого объекта есть поле `id`.

### Токен не добавляется в запрос

Проверьте pre-request script. В конце должен быть вызов:

```js
pm.request.headers.set('Authorization', `Bearer ${token}`);
```

### JSON body отправляется неправильно

Проверьте:

- во вкладке `Body` выбран `Raw`;
- формат выбран `JSON`;
- body является валидным JSON после удаления комментариев;
- есть header `Content-Type: application/json`.

Пример header:

```text
Content-Type: application/json
```

### Raw JSON не форматируется

Проверьте текст ошибки. Форматтер показывает строку и колонку, если может определить место проблемы.

Форматтер может закрыть недостающие `}` и `]`, но не может угадать отсутствующие ключи, значения, кавычки или запятые.

### Script не успевает получить токен

Если используется `pm.sendRequest`, перед ним должен быть `await`:

```js
const login = await pm.sendRequest({
  method: 'POST',
  url: '{{baseUrl}}/auth/token'
});
```

### В истории нет request body у старой ошибки

Старые записи могли быть сохранены до исправления истории. Выполните запрос заново: новые ошибочные записи сохраняют request body.
